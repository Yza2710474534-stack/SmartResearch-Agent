# 开发路线

最终目标是面向技术资料研究的多智能体助手。每个阶段必须有可展示、可复查的结果；尚未实现的能力保持为计划。

| 阶段 | 状态 | 范围与验收 |
| --- | --- | --- |
| ① 本地证据报告 | 已完成离线基线；真实模型验收待完成 | 读取三份本地资料，生成引用报告；每条摘录定位到原文；资料不足时明确说明 |
| ② 自动资料收集 | 计划中 | 搜索、网页正文提取、来源去重、超时处理；保存原始来源与获取时间 |
| ③ Agent 编排 | 计划中 | LangGraph Planner、Research、Writer；共享状态；自主选择检索工具与有上限的补搜 |
| ④ RAG 与数据分析 | 计划中 | 分块、Embedding、FAISS；按需分析用户 CSV；数值与图表可复现；没有数据时跳过分析 |
| ⑤ 展示与评测 | 计划中 | Streamlit 界面；固定研究题目；报告导出；与基础流程进行同题比较 |

## 下一个开发任务

在本地配置模型，使用示例资料执行一次 `--provider openai`。逐项核对输出结论、引用摘录和信息缺口，记录运行用量与耗时。该验收完成后，再扩展自动搜索。

## 最终评测记录

1. 任务完成率：预先定义哪些研究问题和报告要素必须覆盖。
2. 证据支持比例：人工检查每项事实是否由所引用的原文支持。
3. 检索质量：检查相关资料是否找到，搜索失败和资料不足如何处理。
4. 延迟与成本：记录运行耗时、请求次数、token 及工具费用。
5. 失败可恢复性：模拟超时、限流、无结果与无效输出，验证最终状态和错误定位。

在获得评测结果前，简历可以描述已实现的证据追溯和校验机制；多智能体、向量检索以及效果提升应在实际完成并验证后加入。
